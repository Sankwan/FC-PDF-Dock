Internal review · Forestry Commission, Ghana · 27 Sep 2026

PDFDock as the Forestry Commission's staff document toolkit

Scope: repository baseline at commit 2a2aa50: frontend, the PDF‑to‑Word service, and the deployment docs. Covers how it currently works, what to fix, how to deploy it across head office and outstation offices, and how to tailor it to FC.

Summary

PDFDock is a good fit for FC and is mostly ready. Ten of its eleven tools run entirely in the staff member's browser. Documents are never uploaded, so hosting the app does not put any FC document on a server. That matters most for outstations: the app installs once and then works with no internet and no local server.

Before rollout, fix five things: remove the Google Fonts call, add security headers that block uploads at the browser level, run PDF‑to‑Word only on the head‑office server (not Railway), stop Compress from turning text into images without warning, and rewrite the public "free / no account" wording for an FC staff audience.

1. How it works today

Runs in the browser, no upload (10 tools)

  • Merge, Split, Compress, PDF→Image, Image→PDF
  • Watermark, Sign (drawn signature image)
  • Protect: real AES‑256 password encryption (qpdf/WASM)
  • OCR: searchable scanned PDFs (Tesseract, English)
  • Word→PDF (office2pdf/WASM, ~47 MB engine loaded on first use)

Needs a server (1 tool)

  • PDF→Word sends the file to services/pdf-to-word (FastAPI + pdf2docx + OCRmyPDF).
  • Well hardened: files held only in RAM (tmpfs), PDF signature check, generic error messages, constant‑time key check.
  • The docs currently recommend hosting it on Railway, a third‑party cloud. That doesn't fit FC's goal.

Delivery

  • Static build (dist/) served by nginx in Docker.
  • Installable PWA on Windows, Mac, Android and iOS, and works offline once cached.
  • Engines are served from its own address, not a CDN.

Rebranding hooks already built in

  • Name, description and theme colour come from .env.<mode>.
  • Accent colours come from three CSS variables in client/src/index.css.
  • Icon: client/public/icon.svg. The header and footer logos are hard‑coded SVG and need a small change.

Build check (27 Sep 2026): TypeScript check passes and npm run build succeeds. The first install downloads about 3.5 MB (14 files). The full build is 62 MB, of which the Word→PDF engine is 48 MB and loads only when that tool is first used.

3. Deployment: head office server plus outstations with no server

The key point: the server only delivers the app, never the documents. After a staff device has loaded the app once, all processing happens on that device. So outstations don't need a server. Each device needs one successful load, then the app works offline and updates itself the next time it's online.

How outstations reach head office

  • Recommended: Cloudflare Tunnel from the head‑office server. It needs no open ports or static IP, and the server makes only outbound connections. The runbook already exists in DEPLOYMENT.md Part 3.
  • If FC already has a VPN or WAN link to regional offices, use that instead and keep the app internal‑only.
  • For a device that can never get online: copy the built app with a small portable web server on USB. The browser won't install it from a file:// path.

Restricting it to staff

  • The app itself contains no FC data, so the main thing to restrict is the PDF→Word service (and the FC branding).
  • If FC staff use Microsoft 365 or Google Workspace email, put oauth2-proxy in front of both. It's free and self‑hosted, and only staff email accounts can sign in.
  • Cloudflare Access is simpler but free only up to 50 users. It suits a pilot, not all FC staff.

4. Tailoring it to the Forestry Commission

Identity

  • Name: FC DocDock or FC Document Tools.
  • Accent: FC green from the logo, taken from the official artwork (not sampled from a JPEG). Keep VITE_THEME_COLOR in sync with it.
  • Put the FC mark in icon.svg, the header and the footer. The install icon needs PNG 192/512 versions for Android and iOS.
  • Footer: "Forestry Commission · No. 4 Third Avenue, Ridge, Accra · Ministry of Lands and Natural Resources" plus an IT helpdesk contact.

Staff‑facing wording

  • Hero: "Handle FC documents without uploading them anywhere."
  • Replace "Free forever" with "Approved for FC staff use" and an acceptable‑use line that references Act 843.
  • FAQ: "Which tools need the head‑office server?", "Can I use this at a district office with no internet?", "Is Sign legally binding?"

FC‑specific presets (small builds)

  • Watermark presets: CONFIDENTIAL, DRAFT, FOR OFFICIAL USE ONLY, CERTIFIED TRUE COPY.
  • "Received" stamp: division (FSD, WD, TIDD, RMSC, Training Centre), office, date, file reference.
  • Metadata: set Author to "Forestry Commission, Ghana" or strip personal names.
  • Page numbering and file references on every page (e.g. FC/FSD/…).

New tools worth adding

  • Redact: permanently black out Ghana Card numbers, phone numbers and signatures before sharing. This is the most valuable addition under Act 843.
  • Scan with phone: camera photos, cropped and straightened into one PDF with OCR, for field staff and forest guards.
  • Organise pages: rotate, delete and reorder.
  • Letterhead: put FC letterhead on an existing PDF.

5. Suggested rollout

Phase 1
~1–2 weeks
  • Create the FC build (.env.fc, colours, logo, wording) and self‑host fonts.
  • Add CSP and security headers. Deploy on the head‑office server with Docker Compose (app + pdf-to-word).
  • Add the Compress lossless mode and warning, plus the "Prepare for offline use" button.
  • Pilot: head office, plus one regional office and one district office.
Phase 2
~1 month
  • Set up Cloudflare Tunnel (or FC VPN) and staff sign‑in in front of the app and PDF→Word.
  • Add Redact, Organise pages, FC watermark and stamp presets, handling for locked PDFs, and Protect permissions.
  • One‑page staff guide plus a 20‑minute training for regional IT focal persons.
Phase 3
later
  • Phone scanning, letterhead tool, an audit footer for signatures.
  • Certificate‑based digital signing if FC adopts a certificate authority.
  • Automated smoke tests, and a scheduled monthly rebuild for security patches.

6. Decisions needed from FC

  1. Internet‑reachable or FC network only? Outstations need some route to head office at least once. A Cloudflare Tunnel is the simplest; an existing FC VPN/WAN is the most private.
  2. Which staff email system does FC use? The answer (Microsoft 365, Google Workspace, or other) decides how staff sign‑in works.
  3. Which domain? fcghana.org currently shows a hosting placeholder page, so confirm which domain IT controls (e.g. a subdomain like docs.) before issuing certificates.
  4. Who approves use of the FC logo and name in the app, and who owns it after rollout (MIS/IT unit)?
